Seven design directions for the PWA suite

Date 2026-10-21 Design system 0d799c0 (main, 0.6.0) Bodega 93ab8af (main, 1.2.5) Scope design-system.css, DS-1..8, LAY-1..4, the 2026-10-18 UX revision, the screens and styles.css of Bodega

Recommendation

  • Visual: Taller. A flat, high-contrast token set. Tokens only, so every app takes it with npm run ds. It reads best in a bright shop and with one hand.
  • Structural: Barra única, as an opt-in layout for the list apps. One bottom bar holds the section, the search and the add action. The bottom bar and the rail stay the suite default.
  • Component: Tarjetas. A row is a card and its start edge shows its status. CSS only, and it reaches all six apps through item-row, list-group and the menu days.
  • Combination: Taller + Tarjetas in DS 0.7.0 (tokens and one component change), Barra única in a later minor as a layout option. Pestañas, Mercado, Pizarra and Mosaico are documented here as rejected with their reasons.
  • Every frame on this page is the real design-system.css 0.6.0 plus the styles.css of Bodega plus one overlay. The toolbars switch theme, hand, density and width. Click a caption to open the mockup alone.

1Baseline: the suite today

Six apps share design-system.css: pwa-template, pwa-shopping-list (Bodega), pwa-wardrobe, pwa-shifts, pwa-nexus and pwa-financial-calculator. A seventh directory, pwa-lists (Stash), also holds a copy; the README does not name it. Nexus and Stash are on 0.5.0, the rest on 0.6.0.

The current direction comes from the 2026-10-18 UX revision: thumb first, soft and calm, green accent. The rules that every direction below keeps: five layers (DS-1), raw values only in tokens (DS-2), breakpoints 600 and 840 only (DS-8), --tap 48px (TAP-1), one focus ring (FOCUS-1), the left-hand mirror (HAND-1), the safe areas (LAY-4), reduced motion, light and dark.

Each direction is applied to the same seven screens of Bodega: Compra full and empty, the add sheet, Recetas, Menú, Ajustes and the walkthrough. The data is sample data. The 720 width shows the rail (LAY-2); 1024 shows the side sheet and, where a direction uses it, the pane layout (LAY-3).

2Visual directions

A visual direction changes the values of the tokens and keeps their names. It is a CSS file that loads after design-system.css. Two of the three need one component block as well; that block is their cost, and it names a token the design system lacks.

2.1 Taller — flat, high-contrast utility

Intent. A tool for a shop aisle: darker text, firmer lines, small radii, no shadow. A hairline ring stands in for every shadow. The accent is a deeper green with more contrast on white. Rows are 52px, the bar 60px.

Problem it answers. Sunlight and a moving hand. The soft look of 0.6.0 loses its surface steps on a dim or reflective screen; this direction draws every edge.

2.2 Mercado — warm editorial

Intent. Paper and ink: a warm background, a terracotta accent, large radii, and a serif display face for the titles. Rows are 60px, the bar 68px. The app feels like a market notebook, not a tool.

Problem it answers. Identity. The suite looks like every Material app; this gives it a voice. It does not answer a usability problem.

2.3 Pizarra — dense monochrome

Intent. Ink on paper, and one signal colour for a state. The main action (primary button, +, the knob of a segmented, the ring) is ink. The selected state (a ticked row, a pressed chip, the current section) is a cobalt blue. Smaller type, 4px radii, square chips, 48px rows, 56px bar.

Problem it answers. Density and scan speed. A list of 20 items fits where 15 fit today, and colour appears only where something changed.

3Structural directions

A structural direction changes where the navigation and the main action live. Both below remove the bottom bar and the rail, so both touch LAY-2 and the body padding of every app. They are shown with the current tokens.

3.1 Pestañas — tabs and pages

Intent. The sections are four tabs under the header. A secondary task is a page, not a sheet: the add screen pushes in with a back button. The add action is a field in a bar at the bottom, where the + button was. The shop lists stay under the tabs at every width; the dock goes.

Problem it answers. Two taps to add: today + then the field. Here the field is always there, and the keyboard pushes it up. It also frees the header of the search button.

Header, tabs, shop chips, search, list, add bar. The list is 48px shorter than today at the top, and the same at the bottom.

3.2 Barra única — one screen, one bar

Intent. The bottom bar, the + button and the dock merge into one command bar: a section chip at the start, the search field in the middle, the + at the end. The chip opens a sheet with the four sections and the tools of the current one (group and sort, finish the trip). Every secondary task stays a sheet. The header keeps the ring and the title only.

Problem it answers. Three bottom layers today (bar, dock, + button) take 176px of a 740px screen. One bar takes 64px and keeps every frequent action in the thumb zone.

4Component directions

A component direction changes one family that every app renders. Both below are shown with the current tokens and the current shell.

4.1 Tarjetas — cards with a status edge

Intent. A row is a card with an 8px gap and a 4px start edge. The edge is the status: accent for an entry that repeats, soft accent for a recipe, muted for a done one. The check circle goes; the body is the tick target, which Bodega already does (item-row-body tick). The same rule set turns the rows of a list-group card and the days of the menu into cards.

Problem it answers. The status of an item is a glyph in its meta line (↻). Here it is visible from a metre away, and a done item sinks visibly.

4.2 Mosaico — tiles for short lists

Intent. A list under twelve entries is a grid of tiles: two columns, three from 600px, four from 840px. A tile holds the name, the meta line and a round mark in the corner: the tick of an item, or the send button of a recipe. A longer list falls back to rows. A group head spans the grid.

Problem it answers. A short list per shop fits one screen with no scroll, and a tile is a bigger tap target than a row.

6Recommendation

Visual: Taller. It is the only direction with no component cost and no new token, it raises contrast where the apps are used, and it keeps the green. Mercado is the most distinctive, and the right call for Wardrobe alone: an app may set its own --accent and --font-display in its tokens layer once the design system takes the display-font rule. Pizarra's one lasting idea is the split of --primary from --accent; take the tokens, not the look.

Structural: Barra única, for the list apps (Bodega, Stash) and as an opt-in layout of the template. It keeps the thumb-first direction of 0.5.0 and returns 112px of list to a phone. It is not the suite default: Calculator has no list, Shifts no search. Pestañas is the right shape for Calculator alone and is rejected for the suite: the tabs leave the thumb zone.

Component: Tarjetas. CSS only, one markup attribute, and the status edge works in every app that has a row with a state. Mosaico is rejected: two render paths and a loss of the swipe gestures for a gain that only a short list sees.

Sequence. DS 0.7.0: the Taller tokens, the Tarjetas rules, the repeat state, and the --primary and --font-display tokens with their defaults (no visible change until an app sets them). Then npm run ds in the six apps and in Stash; Bodega adds data-repeat in rows.js and redraws the row page of the walkthrough. DS 0.8.0: command-bar as a layout option, with LAY-2 rewritten as "the navigation is .nav-bar or .command-bar", and Bodega and Stash opt in. Each step is a spec change first (DS-1..8, LAY-1..4 and the app rules), as docs/spec/ requires.

7How to try each direction

  1. The frames on this page — each toolbar switches light and dark, right and left hand, normal and compact density, and 360, 720 or 1024 px. A caption opens that mockup alone in a tab.
  2. The catalogue of the design system — npm run serve, then http://localhost:8090/?css=docs/design-alternatives/themes/theme-utility.css (or theme-editorial.css, theme-mono.css). Every component of the catalogue takes the theme.
  3. The live app — the catalogue of Bodega takes no ?css. To see a theme over the real app, add one link after styles.css in index.html, uncommitted: <link rel="stylesheet" href="../pwa-design-system/docs/design-alternatives/themes/theme-utility.css"> served from a parent directory, or copy the file next to styles.css.
  4. Rebuild after an edit — node docs/design-alternatives/build.mjs writes the 57 mockups and this page again from src/ and themes/.

The folder docs/design-alternatives/ is committed, so the page is also on the Pages site under docs/design-alternatives/. No file outside it changed in either repository; version.json is untouched.
